## Commands

- `npm run dev`: dev server (port 3000; QA scripts take `QA_BASE` or `--base` for another port)
- `npm run lint` (eslint), `npx tsc --noEmit -p .` (types; no test runner exists)
- `npm run jysk:check`: builds every guide from `src/data/jysk-rows.ts`, then `qa:overlaps` checks each model. Must end with "600 of 600 guides have no clashes ... no floating fittings". CI (`.github/workflows`) and `prebuild` run it, so a failing guide never deploys.
- `npm run qa:overlaps -- --only <slug> [--why]`: one guide's clash check, with the clashing boxes
- `npm run qa:snapshots -- [--only a,b | --family LIMFJORDEN | --all]`: draws every view (finished, opened, X-ray, each step) and diffs against `.qa/baseline`; review `.qa/report.html`, then `-- --approve [--only ...]`. Without a selection it draws only guides whose family file or row changed since the last commit, so engine changes need `--all`. Also flags fittings visible before their step fades them in (`.qa/ghost`).
- `npm run qa:callouts -- [--family X | --only a,b]`: checks every step's zoom circles at desktop and phone size (in view, clear of the UI, each other and the step's fittings)
- Snapshot and callout QA need the dev server plus Playwright (`PLAYWRIGHT_FROM`, a folder whose `node_modules` has it). They render through `/dev/og` with SwiftShader.
- `npm run families`: regenerates `src/lib/plan/families/index.ts` after adding or renaming a family file (never edit that index by hand)
- Running a TS script directly: `node --no-warnings --import ./scripts/voice/register.mjs <file.ts>` (the loader resolves `@/` paths)
- `npm run jysk:refresh` / `jysk:build`: the JYSK catalog import (see README). An unclassifiable product stops the build: extend `classify()` in `scripts/jysk/build.ts`, never skip it.

## Architecture

The pipeline is: catalog row → `ProductSpec` → `Plan` (pure data) → `Stage` (three.js) renders it.

- **Catalog**: `src/data/jysk-rows.ts` (generated by `scripts/jysk/build.ts`; one-off corrections in `src/data/fixes.ts`), decoded by `src/lib/ikea.ts` and looked up by slug in `src/lib/catalog.ts` (`catalogSpec`).
- **Plan generation** (`src/lib/plan`): `buildPlan(spec)` in `index.ts` asks a family first, then falls back to the archetype's generic builder (`shelf.ts`, `drawers.ts`, `cabinet.ts`, `bed.ts`, ...).
  - `families/<name>.ts` export a `Family` (`family.ts`), matched by the first word of the product name. A family either `build`s with `PlanBuilder` directly or returns a `recipe` of boxes and steps that `custom.ts` turns into a guide, working out the fittings. It returns null/false for a product it doesn't cover. Files starting with `_` are shared helpers (`_wall.ts` wall fixing, `_seat.ts`, `_metal.ts`).
  - `builder.ts` (`PlanBuilder`, `HW` fitting defs, `SIDE_DOWN` marks) produces the `Plan` described in `src/lib/types.ts`: part types and items, hardware types and items, holes, step poses (`pose`, camera `turn`), scenes and step contents.
  - Manual-based families (e.g. `limfjorden-*.ts`, `jenslev.ts`) carry measured drilling with comments naming the manual page. Positions come from the manual's to-scale parts pages, not guesses.
- **Engine** (`src/engine`): `stage.ts` is the one `Stage` class: modes (intro, assembled, part, step, ...), step animation (insert, turn for cam locks/screws), camera, and zoom callouts (`placeCallouts`, one circle per fitting, sticky across steps). `drawable.ts` builds line-art meshes for parts and every hardware kind; `sizes.ts` holds shared fitting dimensions (also read by `qa:overlaps`); `thumbs.ts` renders snapshots.
- **UI**: `/build/[slug]` renders `src/components/guide/GuideApp.tsx` (step panel, parts, tools, done, print view under `print/`). Fitting icons in the side panel are SVG in `src/components/art/Hardware.tsx`, separate from the 3D drawables, so a fitting shape change usually touches both.
- **Dev renderer**: `src/app/dev/og` exposes `window.__callouts`, `__compare` etc. for the QA scripts and `scripts/og/render.mjs` (share cards). `scripts/og/browser.mjs` is the shared headless-browser setup.
- AI (Together, on each visitor's own key) and voice are off unless `NEXT_PUBLIC_AI=1` (read at build time).

## Working on guides

- A change in `drawable.ts`, `stage.ts` or `builder.ts` affects every guide: run `jysk:check`, then `qa:snapshots -- --all` and approve before committing.
- Checking a family against its manual: the cached product page in `scripts/jysk/cache/<category>__<slug>.html` links the "Assembly instruction" PDF. Render a parts page with `pdftoppm -f N -l N -r 600 -gray` and measure hole positions on the panel drawing.
- WebGL views can only be checked in a real (headless) Chrome; the snapshot tooling is the usual way.
